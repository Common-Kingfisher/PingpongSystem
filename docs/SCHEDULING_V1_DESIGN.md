# 比赛时间记录（当前定稿范围）

更新日期：2026-09-09。

## 本期实现

时间记录功能增加以下两个事实字段；保留最新基线已实现的调度排序：

当前 `schedule-next` 已按 硬约束 → 组台亲和 → 组间进度公平 → 连续上场软惩罚 → 稳定确定性排序 选择比赛：同一运动员不会同时上两场、同一球台不会同时放两场，并优先避免刚完成比赛的运动员立即再次上场（软性排序，在没有其它可执行比赛时仍允许继续安排）。A2 之后 `matches` 已有 `called_at` / `started_at` / `finished_at`（UTC），"刚打完"已优先按真实 `finished_at` 排序；`GET /api/tournaments/{id}/schedule-estimates` 提供只读的预计上场时间（复用同一套排台规则），但尚未记录推荐理由、主裁判覆盖原因，也没有分钟级最短休息保证与预览/确认流程。选手赛程页也是只读查询，不是调度工作台。

- `matches.called_at`：最近一次安排上球台的叫号事实。
- `matches.started_at`：当前有效上台过程的开始时间；释放球台后清空，再次安排时重写。
- `matches.finished_at`：当前有效比赛第一次产生结果的时间；赛后改分不覆盖。

WAITING 直接录分只写 `finished_at`，不伪造 `started_at`，因此不会进入真实耗时样本。

比分修改、补录逐局小分和裁判备注修改均不得覆盖上述时间。它们有独立的比分审计时间。

历史数据库迁移后允许两个字段为空，页面显示“—”，不根据创建时间或最后修改时间猜测。

## 明确暂缓

- 不增加 `called_at`、预计开赛时间、最短休息时间或调度版本。
- 不建设调度策略、批次和安排审计表。
- 不改变现有手动排台与自动填充空闲球台的方式。
- 本 PR 不增加备份/恢复入口；保留最新基线已有的结构化赛事导出能力。
- 官方秩序册模板取得后再单独设计渲染适配。

## 验收

- 首次上台有 `started_at`，释放并重新上台不改变它。
- 首次完赛有 `finished_at`；直接录分时两个时间均存在。
- 修改大比分或补录小比分后，两个时间保持不变。
- OpenAPI、TypeScript 类型、控制台展示和后端测试同步更新。
