## 2. 接口契约

### 2.1 查询协作管理员

`GET /api/tournaments/{tournament_id}/admins`

仅 `OWNER` / `ADMIN` 可访问。返回赛事 Owner 与未撤销的普通协作管理员。Owner 行由 `tournaments.owner_user_id` 生成，不重复返回 `tournament_admins` 中的 Owner 影子记录。

返回字段：`user_id`、`username`、`display_name`、`role`、`active`、`is_owner`、`created_at`、`created_by_user_id`。不返回密码散列、Session Token、Token 散列或其他认证敏感字段。

### 2.2 新增或更新协作管理员

`POST /api/tournaments/{tournament_id}/admins`

请求体：

```json
{
  "user_id": 123,
  "role": "OPERATOR"
}
```

语义：

- 仅 `OWNER` / `ADMIN` 可操作。
- 允许授予 `ADMIN`、`OPERATOR`、`VIEWER`。
- 同一赛事与用户重复授权按 upsert 处理，更新角色但不产生重复行。
- 已撤销授权重新添加时恢复 `revoked_at = NULL`。
- `created_by_user_id` 始终来自当前认证用户，不信任客户端传入。
- Owner 只能来自 `tournaments.owner_user_id`，普通接口不能授予或转移 Owner。

### 2.3 撤销协作管理员

`DELETE /api/tournaments/{tournament_id}/admins/{user_id}`

- 仅 `OWNER` / `ADMIN` 可操作。
- 使用 `revoked_at` 软撤销，保留历史记录。
- 重复撤销仍返回 `204`。
- 撤销后同一 Session 的下一次赛事写请求立即失去赛事权限。
- 不允许通过此接口撤销赛事 Owner。

## 3. 权限与错误语义

| 场景 | 状态码 | 错误码 |
|---|---:|---|
| 未登录、凭据冲突或 Session 失效 | 401 | `AUTH_REQUIRED` |
| 无赛事权限、跨赛事、Operator / Viewer 访问管理面 | 404 | `RESOURCE_NOT_FOUND` |
| 无效赛事角色，包括 `OWNER`、空字符串和超长字符串 | 422 | `INVALID_TOURNAMENT_ROLE` |
| 试图通过普通接口变更赛事 Owner | 409 | `OWNER_PROTECTED` |
| 普通撤销成功或重复撤销 | 204 | 无响应体 |

目标账号必须是存在、`active=true`、系统角色为 `EVENT_ADMIN` 的用户。`SYSTEM_ADMIN` 不自动获得赛事业务权限，也不能作为普通协作管理员目标。

## 4. 异常结果接口配合边界

D3A 不新建 `/abnormal-result` 等第二写入口，继续复用：

- `POST /api/matches/{match_id}/score`
- `POST /api/matches/{match_id}/revise-score`

A 轨负责：

- 真实登录态解析；
- 比赛资源归属校验；
- 赛事写权限保护；
- Schema / OpenAPI 契约；
- 401 / 404 等稳定错误边界。

B 轨继续负责比分合法性、异常结果业务规则、改分影响、排名与晋级算法。D 轨继续负责手机端异常结果交互，且前端 Guard 不能代替后端校验。异常结果复用现有 `ScoreRequest` / `ResultType`，继续支持 `FORFEIT`、`WALKOVER`、`NO_SHOW`、`DISQUALIFIED`；BYE 不属于 D3A 的正常比赛异常比分入口。
