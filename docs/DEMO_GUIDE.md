# 乒乓球赛事编排与赛务管理系统 Demo — 操作手册

## 1. 启动

```bash
# 终端 1：后端（端口 8000）
cd backend
.venv\Scripts\activate            # Windows；首次需先创建 venv 并 pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# 终端 2：前端（端口 5173）
cd frontend
pnpm install                      # 首次
pnpm dev
```

浏览器打开 <http://localhost:5173>。

## 2. 准备 Demo 数据（三种方式）

### 方式 A：种子脚本（一键就绪）

```bash
cd backend
.\.venv\Scripts\python.exe seed_demo.py          # 重建：加 --fresh
```

自动创建「演示赛事（24人/6台）」：24 名选手（选手01~选手24）、6 张球台、
4 组 × 6 人、每组前 2 晋级，并已生成全部 60 场小组赛（待赛状态）。
输出 `id` 后，直接打开 <http://localhost:5173/?tid=<id>。

### 方式 B：Excel / CSV 批量导入（推荐演示名单录入）

`docs/demo-data/` 内置两份 16 人名单（4 学院轮换，选手01~04 为 S1~S4）：

- `demo_players_16.xlsx`
- `demo_players_16.csv`

流程：创建赛事（正式或演示）→ 参赛名单 → 「Excel / CSV 导入」→ 选文件 →
「预览并校验」核对全部行 → 「确认导入 N 人」→ 名单立即出现。种子不再属于名单导入的推荐字段，
请在「抽签与编排」中由主裁人工设置。
也可点击「下载 CSV 模板」自制名单。导入是正式能力，LIVE 赛事同样可用；只有「生成演示选手」限演示赛事。

### 方式 C：手工全流程（演示完整操作路径）

1. **首页**：创建赛事时选择“演示赛事”（球台/小组/晋级数/局制/每局目标分按需）→ 进入「参赛名单」。正式赛事不会显示模拟按钮，后端也会拒绝演示接口。
2. **参赛名单**：手动添加、`Demo 生成演示选手`或 Excel/CSV 导入 → 确认线上报名 → 整体确认参赛名单。
3. **抽签与编排**：按赛事赛制显示适用能力；小组淘汰赛可人工设置种子、抽签分组并生成小组比赛。
   全体循环赛与单淘汰的正式生成入口尚未开放时，页面会明确显示等待后端契约，不伪造成功。
4. **比赛控制台**：「自动安排下一批比赛」按 硬约束 → 组台亲和 → 组间进度公平 → 连续上场惩罚 填充球台（4 组 4 台时稳定保持 A→1、B→2、C→3、D→4）→ 按赛事配置录入大比分（默认三局两胜时为 2:0 / 2:1）→ 循环完成；连续上场只是软性排序（没有其它可执行比赛时仍会安排），且尚未实现正式赛事的分钟级休息时间与预览确认；
   需要跳过时可用「`Demo` 模拟完成剩余小组赛」一键生成剩余结果（比分按赛事局制生成）。
5. **小组排名**：查看各组名次与「✅ 晋级」标记；已结束的小组赛可补录逐局小比分。补完可用小分后晋级线仍无法区分时，主裁判可从页面指定准确数量的晋级者，并填写裁定理由和姓名。
6. **赛前检查**：从左侧导航进入，先处理“阻断”项，再确认“注意”项。该页只读，不会替主裁确认名单、生成比赛或指定晋级者。
7. **退赛验证**：比赛开始后在“抽签与编排”的小组卡片点击“退赛”，填写主裁判和原因；确认既往赛果保留、未赛场次判负、排名显示“已退赛/不参与晋级”。本场临时弃权仍从比分弹窗处理。
8. **淘汰赛**：「生成淘汰赛」→ Bracket 上直接点「录入大比分」，胜者自动晋级下一轮；
   打完决赛产生 🏆 冠军。
9. **赛事大屏**：`/bigscreen` 约 2 秒自动同步，展示进行中比赛、球台、排名摘要、
   淘汰赛 Bracket 与冠军画面（只读，适合投影/电视）。
10. **在线报名**：`/register` 供选手自助报名（无账号），管理员名单页约 5 秒自动刷新。

### 方式 D：120 人规模验收

使用 `docs/demo-data/realistic_players_120.csv`（或同目录 XLSX）导入 120 人赛事。推荐配置为 15 台、24 组、每组 5 人、每组前 2；完整验证命令和预期场次见 `docs/SCALE_VALIDATION_120.md`。这是确定性容量回归数据，不要当作真实报名名单发布。

> 录错比分？控制台「已结束比赛」或 Bracket 中修改（淘汰赛若后续已开赛会阻止修改并提示）。

## 3. 页面一览

| 页面 | 地址 | 功能 |
|---|---|---|
| 赛事首页 | `/?tid=` | 赛事信息、阶段、进度条、各页入口；创建/删除赛事 |
| 赛前检查 | `/preflight?tid=` | 主裁只读核对名单、分组、赛程、球台、晋级和规则状态 |
| 参赛名单 | `/players?tid=` | 运动员增删改查、Excel/CSV 导入、待确认报名审核、整体名单确认 |
| 抽签与编排 | `/draw?tid=` | 按赛制展示种子、分组、编排和后端能力就绪状态 |
| 赛事设置 | `/settings?tid=` | 赛制、报名、组织方、场馆、Public 地址、导出和删除 |
| 比赛控制台 | `/console?tid=` | 现场球台舞台（安排/录大比分/下球台）、自动排台、待赛队列、改分、Demo 模拟 |
| 小组排名 | `/rankings?tid=` | 各组名次/胜负/净胜局/是否晋级 |
| 淘汰赛 | `/knockout?tid=` | Bracket 图 + 只录大比分 + 冠军/亚军 |
| 选手赛程 | `/schedule?tid=` | 按选手查询小组/种子/下一场/历史（只读） |
| 赛事大屏 | `/bigscreen?tid=` | 只读大屏：进度、进行中比赛、球台、排名摘要、Bracket、冠军（2s 轮询） |
| 在线报名 | `/register?tid=` | 选手自助报名（姓名/学院，无账号） |

## 4. 运行自动化测试

```bash
cd backend
.\.venv\Scripts\python.exe -m pytest -v
```

自动化测试覆盖：分组（含种子分散）、循环赛（6 人=15 场）、球台调度、
比分与改分（不累计污染、淘汰赛改分守卫）、排名、淘汰赛（晋级/输家不复活/唯一冠军）、
种子分区（1/2 号种子分处上下半区；偶数组每组前二按首尾交叉，2 组与 4 组为已冻结用例，4 组即 A1-D2、C1-B2、B1-C2、D1-A2；需要轮空时的轮空落位与奇数组未正式冻结）、Demo 功能（生成选手/模拟小组赛）、
Excel/CSV 导入（表头别名/容错/种子）、正式/演示隔离、比分请求幂等和端到端全流程。测试数量不在手册中硬编码，以实际测试输出为准。

## 5. 已知限制（技术债）

- 排名并列：系统先应用既定自动规则；仍跨越晋级线时不编造名次。补完可用小分后，主裁判可以人工补足剩余晋级名额。裁定不改变原始排名，并记录理由、操作者和时间；相关成绩或出线人数变化会使其自动失效。
- 淘汰签支持各组独立出线人数与轮空；完整名次排位对 4 / 8 / 16 人无轮空标准签有效，带轮空或超过 16 签时只输出由真实比赛确定的名次。需要轮空时的轮空落位与奇数组规则尚未正式冻结（当前为确定性兼容实现）。
- 季军产生方式在创建赛事时确定：可选半决赛负者进行季军赛，或两人并列季军。
- 淘汰签在尚未开始时可以撤销（回到小组赛阶段）后修正比分重新生成；一旦有比赛开始或已录结果，撤销会被拒绝。
- 调度为启发式排序（硬约束 → 组台亲和 → 组间进度公平 → 连续上场软惩罚 → 稳定顺序），非全局最优，不预测时长；连续上场只是软性排序，没有分钟级休息保证。
- 小组赛生成后不可重新分组（名单锁定），需 `--fresh` 重建赛事或 ungroup 前置。

## 6. 当前不支持的功能（OUT_OF_SCOPE）

用户登录/权限系统、裁判/选手正式账号、支付、短信/微信通知、小程序/App、
长期积分与全国排名、历史档案、社交、AI 排赛/裁判/视频识别、云部署/K8s/微服务/
Redis/Kafka/ES、复杂规则引擎、种子排名与同单位规避、手动拖拽调组、.xls/ods 导入、
报名联系方式采集（可选字段，Demo 未采集）。当前先面向单一主裁判操作，不把自由填写的操作者姓名视为账号认证。
